# Coordinator slice 2: Codex opt-in and worker process adapter

Status: implemented and independently reviewed for the bounded slice; see the execution report, 2026-10-04. Baseline `37df240`; Python 3.11+ standard library, Git, one local Linux/ext4 clone and linked worktrees. This implements [delivery outline slice 2](v1-delivery-outline.md) on the [state core](state-core-usage.md). It does not establish the six-scenario pilot, independent review provenance, effective permissions in all configurations, or unattended host recovery.

## Package and explicit opt-in

`coordinator/package/manifest.json` is the **source allowlist**, with format version and exact source/destination paths. Task 1 enumerates `coordinator/package/run.py`, existing runtime files in `coordinator/coordinator_core/`, new `installation.py`, and `coordinator/package/AGENTS.block.md` as a managed block source; Task 2 adds its actual runner/receipt files. No recursive copy or speculative entries. `coordinator/install.py` computes current SHA-256 hashes when previewing; the installed `.bmad-coordinator/manifest.json` pins those hashes, package revision, and managed-block hash. This avoids stale hand-maintained source digests when runner files change. Tests, plans, research, experiments, `_bmad-output`, runtime DB, run logs, checkpoints, and private tokens are absent from the allowlist and destination. A thin `.bmad-coordinator/run.py` sets `sys.dont_write_bytecode = True` before importing `coordinator_core.__main__.main`, allowing `python3 .bmad-coordinator/run.py --repo /absolute/worktree status` without global installation or untracked `__pycache__`; do not alter project `.gitignore` for this. Distribution instructions belong in `coordinator/README.md`; the starter's already-dirty root README is outside this slice.

`python3 coordinator/install.py --repo /absolute/target --preview` is read-only and shows the exact root `AGENTS.md` addition, destination file list, hashes, collisions, and a SHA-256 preview token over source manifest/files plus target bytes-or-absence; `--upgrade` refreshes an installed package in place (2026-10-13). `--apply --preview-sha256 TOKEN` rechecks every input, refuses stale previews, stages only absent package files, and appends the managed block **last**. The block uses `<!-- bmad-coordinator:begin v1 -->` / `<!-- bmad-coordinator:end v1 -->`. Existing instruction bytes outside it remain exact. Exact repeat is a no-op; changed markers, package bytes, symlinks/nonregular paths, or divergent partial installs fail. A crash before activation can fill only missing paths when all existing package bytes match. An activated but damaged install needs an explicit reviewed repair/update; no force flag. Warn if Git ignore rules prevent tracking package files. `coordinator/README.md` describes this separate opt-in while the starter root README's BMAD copy set stays untouched; no installer writes any real project without explicit `--repo` and apply token.

`coordinator_core.installation.doctor(repo: RepoIdentity, base_ref: str) -> DoctorReport` is read-only and does not initialize coordinator state. The CLI `doctor --base REF` reports `ready`, package revision, resolved base commit, and precise reasons. It validates the actual worktree's block and installed file hashes, resolves REF to one concrete commit, requires that commit to be an ancestor of the actual feature `HEAD`, then inspects that **base Git tree** for the exact committed package and block. An unrelated installed commit passed as REF cannot make a dirty copied install look ready. Before feature worktree creation, resolve the intended base with Git and record that exact commit in `FeatureInput.base_commit`; `base_ref` records the user's declared ref, which may move later and is not used to reconstruct historical provenance. Before launch, repeat doctor against the assignment feature's recorded `base_commit`; verify its actual worktree/common directory and `git symbolic-ref --quiet --short HEAD` branch equal the recorded worktree path/common directory and `FeatureInput.branch` string. Reject detached HEAD for this first runner. The feature fields are declared provenance at creation; doctor and runner add verified checkout evidence without broadening `create_feature` validation or changing existing fixtures. No auto-copy, auto-commit, target reset, or dirty-tree transplant.

The block routes ordinary substantial requests through discovery, installed BMAD inspection, mandate/authority recording, and fenced CLI state; small direct tasks remain direct. A frozen runner envelope explicitly says `role: worker` for `workspace-write` assignments or `role: reviewer` for `read-only`, repeats the mandate, scope, exclusions and input fingerprints, and prohibits **top-level** intake and owner claim. Bounded nested work/review remains permitted by the assignment and run budget. The first adapter supports these two permission modes only; a read-only author role needs an explicit later contract rather than an inferred one. For `read-only`, `writable_paths` must be empty; `author_id` still names the reviewer actor and implies artifact authorship only if a changed-path return actually supports it. Make the narrow core `create_assignment` exception for empty paths in this mode, while other modes retain their nonempty requirement; reject nonempty paths for read-only. No schema migration. The block makes no promise of automatic worker launch or unattended recovery.

## One process attempt and evidence

New CLI commands: `worker run ID --token-file PATH --model MODEL --timeout SECONDS`, read-only `worker inspect ID`, and owner-fenced `worker reconcile ID --token-file PATH`. Existing top-level `--repo` precedes them. `run` accepts only a prepared assignment from the current owner, validates its source/contract digests and installed package, and refuses any existing attempt sidecar, reserves launch through the fenced database transition, then creates exactly one mode-0700 sidecar directory at `<git-common-dir>/coordinator/runs/<sha256(assignment-id NUL request-fingerprint)>` with exclusive creation. The raw imported ID is never a path component. A second concurrent `run` sees the sidecar or loses the fenced reservation and refuses. Expected dependency or decision refusal happens before attempt files are created, so resolving that prerequisite leaves the prepared assignment usable. `reserve_launch` persists intent **before** exclusive sidecar creation and `Popen`; a crash after that reservation leaves the assignment reserved/unknown and a second call never blindly spawns. A pre-existing sidecar also remains a refusal, even if database state is still prepared. No schema migration is needed: use existing assignment fingerprint, launch/return transitions and `EvidenceSource`; sidecar receipts hold process detail.

The runner writes the exact UTF-8 frozen brief/envelope and its hash, return JSON schema, requested sandbox, model, argv, cwd, source/contract fingerprints, assignment ID and request fingerprint to the sidecar. Invoke an argv array, never a shell: `codex exec - -C WORKTREE --sandbox read-only|workspace-write -c approval_policy=never --json --output-schema SCHEMA --output-last-message LAST -m MODEL`. Feed brief bytes to stdin. Do not use `--worktree`, `--ephemeral`, `--ignore-rules`, permission bypass, global config changes, or a managed worktree chosen by Codex. Record CLI version/config provenance when available without reading secrets. Stream raw JSONL and stderr to mode-0600 sidecar files. Requested mode/argv is **not** proof of effective permission; record effective enforcement only from observed tool/OS evidence. A preliminary disposable two-process probe (to be archived with Task 3 evidence) observed one workspace write, but its read-only subject *claimed* a denial without a write command event: that denial remains unverified.

`return.schema.json` generated in the sidecar has exact required fields: `assignment_id: string`, `request_fingerprint: string`, `result: "completed" | "needs-decision" | "blocked"`, `changed_paths: string[]`, `checks: string[]`, `descendants: string[]`, `unresolved_question: string | null`, `options: string[]`, `affected_ids: string[]`; no extra fields. The worker's checks, permission assertions and descendants are **claims**. Validate final JSON again in Python without a non-stdlib JSON-schema dependency. Require matching ID/fingerprint, exit 0, one `thread.started` ID and matching terminal `turn.completed`, valid last-message bytes, and no contradictory terminal failure. A valid `blocked` or `needs-decision` result is an observed *transport return* with that state, never a completed deliverable.

Before launch, snapshot tracked and nonignored untracked worktree path/type/content hashes using Git plus file reads; snapshot again after terminal exit. Resolve paths canonically, detect added/changed/deleted files and symlink changes, and compare **all observed deltas** with the assignment's exact writable paths. For a completed author return, worker `changed_paths` must equal the observed delta and current SHA-256 digests; a deletion, out-of-scope delta, or moving file invalidates observed completion and remains blocked/unknown for manual correction. The brief and installed contract files must be immutable for this assignment and outside its writable paths. Recheck them and other read-only sources after return. A source artifact that is itself an authorized correction target may change: preserve its original digest as frozen input provenance and accept only the measured, allowed new digest. For read-only reviewer, any delta blocks the result. A later filesystem mutation can still occur, so review/acceptance recheck current bytes separately. Ignored files, external paths, hooks, and descendants are not fenced by this inventory or by assignment path instructions. Preserve unexpected changes for inspection; never revert them automatically.

Write separate immutable launch/terminal receipts with payload digests; the `ReceiptEvidenceSource` validates receipt bytes, assignment/fingerprint, process/thread/event linkage and measured path hashes before returning `observed` for launch/return. It always returns `reported` for `classify_review`: worker output is not independent review evidence. The DB `LaunchEvidence`/`ReturnEvidence` uses refs such as `runs/<digest>/launch.json` **relative to `<git-common-dir>/coordinator`**, with receipt digest, never absolute paths. `ReceiptEvidenceSource`, `inspect`, and `reconcile` resolve that same base; existing checkpoint validation must still export worker-observed assignments. Sidecar runtime bytes are not exported; imported refs are historical/unresolved, never reusable process proof in another clone. The sidecar stores raw events, PID/process group, timestamps, exit, requested sandbox, effective-permission evidence if any, and measured bytes. Before recording or replaying a terminal return, persist its digest in an owner-fenced event in the existing database; validate launch receipts against their persisted launch-event digest as well. A crash between sealing a terminal file and recording its database anchor remains unknown. Reconciliation must not create an anchor from unanchored sidecar bytes. Compare every final-result field with the anchored receipt, and verify the private regular frozen envelope against the already anchored launch envelope digest on initial return and later inspection/reconciliation. Read-only inspection and reconciliation preserve historical DB claims but report current evidence as unknown when receipt or file validation fails. Record end/exit metadata for unsuccessful and malformed returns, and attempt bounded process-group cleanup on post-spawn interruption including KeyboardInterrupt. `inspect` is read-only. `reconcile` can idempotently bind an already verified terminal receipt to a current owner-fenced DB record, but never launches/resumes a process or grants takeover. Missing/failed terminal event, partial receipt, malformed JSON, timeout, permission denial, process loss, or file drift yields `unknown`/blocked with evidence needs. Timeout sends TERM then KILL to the process group and records both attempts; even a dead PID does not prove descendants/hooks stopped. Existing release and takeover remain conservative.

## Validation gates

Disposable Git repository tests cover exact/no-clobber install and doctor, committed linked-worktree propagation, dirty-base refusal, unrelated-installed-base refusal, no installed bytecode cache, read-only assignment creation/zero-delta and mutation refusal, two simultaneous run calls with one sidecar/spawn, crash windows around reserve/spawn/receipt, malformed/wrong-ID/blocked/needs-decision returns, path aliases/out-of-scope edits, immutable-source drift, authorized source-target corrections, missing terminal event, portable-ref checkpoint export, timeout and idempotent reconciliation. Preserve the existing 88-test baseline and reported-evidence default. Actual named Codex CLI probes must show one completed file authoring return with raw event/file evidence, a read-only **actual attempted write** and denial (otherwise permission gate blocked), and timeout/unknown refusal in a disposable repository. A transparent fixture permission self-test script may produce an actual OS write attempt/result when instructed, but a final-model claim alone cannot. A fresh ordinary request tests `AGENTS.md` activation without seeding the coordinator route; a fresh worker brief tests role suppression; a second conversation tests owner conflict. Ordinary activation observed under a read-only main-session sandbox proves routing/status only, not successful SQLite owner claim, because writes to Git common state may be denied. Record client/version, instruction hash, prompts and events actually available, intervention count, and limits. Native desktop experiments remain separate evidence.
