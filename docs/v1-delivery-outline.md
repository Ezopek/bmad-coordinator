# Coordinator v1: staged delivery outline

**Status:** proposed build sequence, 2026-10-04. This is a review aid for the [v1 design](v1-design.md), not implementation evidence or approval of a detailed spec. Each slice earns its next dependency through observable acceptance, rather than promising every future client or BMAD workflow at once.

## 1. Local state and ownership core

Build the Python standard-library CLI and SQLite store under the canonical Git common directory. Define a minimal versioned schema for owner epoch, feature mandate/decisions, assignments, reviews, acceptance, events, and export revision. Add status, claim/handoff/recover, assignment reconciliation, decision/return, digest verification, and export commands. The database is canonical local coordinator state; a JSON checkpoint and readable handoff derive from one revision, with atomic write/readback and validated import, never silent commit. Exercise simultaneous claim, stale token, crash between launch intent and worker ID, precheck-to-external-launch race, export pending, manual export drift, and later artifact mutation. Recovery refuses blind retry or stale acceptance. Transaction fencing stops old **CLI state changes**; affected writers and launchers require proven quiescence or tested isolation.

## 2. Opt-in and first worker path

Package portable repository instructions and CLI files without adding fixtures, research, or runtime state to the starter copy set. Install non-destructively beside existing instructions. Verify ordinary request activation, worker-role suppression of recursive coordination, and opt-in propagation to a new feature worktree. A dirty bootstrap absent from the worktree base must be detected; do not clone user changes to hide the problem. Implement Codex CLI `exec` as the first worker process adapter, invoked by the main opted-in Codex conversation, with explicit cwd, frozen brief, effective permission mode, event/return capture, and unknown-state reconciliation. Probe interrupted process, permission denial, wait/return, and read-only review. Keep native desktop subagents as a separately evidenced experimental path.

## 3. Installed BMAD planning integration

Discover installed catalog, contract files, configuration and overrides; fingerprint the exact bundle. Bind feature PRD and architecture assignments to those contracts and the mandate. Give workers authority inputs, writable paths, exclusions, role, and return evidence. A worker owns its artifact and corrections; a distinct reviewer examines a verified content-addressed bundle of exact versions and dependencies. Route `NEEDS_DECISION` from an interactive BMAD gate to the coordinator: answer within mandate with provenance, or ask the operator only when authority is missing. If the adapter cannot resume that gate, show it as unsupported. Serialize shared project-file changes; keep sprint topology and Loop out of this slice. Recheck current content against reviewed digests on acceptance, resume, and handoff.

## 4. Six-scenario planning pilot

Run the full accepted pilot in a disposable repository for the **named Codex conversation plus CLI worker-adapter path**. Retain ordinary request and activation trace; discovery/mandate and worktree evidence; bounded PRD/architecture briefs, returns, controlled scope-error correction and independent review; interrupted-session recovery; competing-session and stale-owner recovery; and a final reviewed planning handoff. Include the parked feature and blocked-dependent/advancing-independent task checks. Ownership requires evidence that old sessions **and affected workers** do not write after handoff; DB epoch rejection alone is insufficient. If the client cannot prove stop or isolation, report that scenario blocked and withhold first support claim. Score each scenario separately as pass, fail, or blocked, with versions, diffs, client/permission identity, and intervention count. The two probes remain narrower evidence.

## 5. Unattended continuation gate, then growth

Immediately after the first-client planning gate, prove prolonged independent progress with actual host liveness or an explicitly started bounded foreground driver that runs/resumes coordinator turns from persisted state under transferred ownership. The interactive conversation cannot keep a competing owner; operator decisions/stop reach that run or pass through handoff. Reconcile ambiguous launches, honor permissions, and expose `continue`, `needs-human`, `done`, or `failed`. A manual resume cannot establish overnight operation. Then test Claude Code, Copilot CLI, and Copilot IDE chat as separate adapters and pilots. Test concurrent features, installed BMAD numeric epic IDs, Loop ownership, internal branch integration, and reviewed local commits as separate gates. Push, target-branch merge, deployment, data deletion, and BMAD package updates retain separate mandates.
